# 已知限制与验证矩阵（0.2 工程预览）

本文约束本包的验收口径。需求文档里的 API 形状可以看；**本包只保证下表「已验证」列。**

内部产品说明：[需求文档.md](需求文档.md)。供应商接线：[供应商集成说明.md](供应商集成说明.md)。真机按接线检查见本文第 5 节。

---

## 1. 本包是什么

`drone-fc` **0.2** 是内部工程预览，不是已验收的多机型商用 SDK。

已验证：打开 URI、等到 PX4/ArduPilot 飞控 `HEARTBEAT`、超时/非飞控心跳排障、心跳过期后的 `LinkLostError`、调用方 `reconnect()`。协议 mock 为 **PX4 四旋翼**。

未作为本包验收项：固定翼/垂起真机或 SITL 飞行、航线握手、Offboard 流、云台、图传视频、MAVLink2 signing。

## 3. 行为约定（避免误读）

- **`connect()`** 打开套接字或串口并等待飞控心跳，不是登录。MAVLink 默认无认证。
- **不自动重连。** `PymavlinkTransport` 将 `autoreconnect=False`。掉线后由调用方 `reconnect()`；USB 重插换节点时用 `reconnect(uri="serial:/dev/ttyACM1:57600")`。
- **`takeoff` / `goto` / `land` / `rtl`** 在飞控 ACK 后返回。到位必须 `wait_telemetry`；超时抛 `TelemetryTimeoutError`，不得继续当成功。
- **本库从不强制解锁。** 预解锁失败看 QGC。进程挂掉后的行为由飞控 RC 丢失 / 机载丢失参数决定。
- **云台 ≠ 摄像头。** `set_gimbal` 是 Gimbal Protocol v2 指向；不做视频流、图传或相机拍照。
- **不烧录固件。** 只与正在运行的飞控走 MAVLink（UDP/TCP/串口），不写 ROM/Flash。
- **遥测订阅。** `connect` 后会发 `SET_MESSAGE_INTERVAL`；发送失败记在 `fc.telemetry_rate_errors`（并打 logging warning），不静默丢弃。位置一直为 `None` 时先查该字典。其中 msg_id=280（GIMBAL_MANAGER_INFORMATION）在总线上无云台时常返回 FAILED/UNSUPPORTED，属正常，云台能力以 HEARTBEAT(`MAV_TYPE_GIMBAL`) 或 `GIMBAL_MANAGER_INFORMATION` 实际出现为准；若该字典只含 280 一项可忽略。
- **本端心跳。** 约 1 Hz，只在 `telemetry` / `wait_telemetry` / `spin` / 等心跳时泵送。`connect` 后若长时间不调这些方法，飞控可能判机载丢失——调用方须继续泵包。
- 运行时依赖 **pymavlink（LGPLv3）** 必须保持 pip 可替换，见 `LICENSE`。本预览未提供 MIT 方言后端。

## 4. 明确不做（本阶段）
- 武器、打击、作战调度
- 无人车 / 船 / 潜艇 API（可识别为 `UNKNOWN` 并拒绝飞行命令）
- 机载设备路径封装、Gazebo/AirSim 统一入口、推理后端、4G/数传桥、多机编队
- MAVLink2 signing（需要隔离网络或串口，不要把 `connect` 成功当成对方不能连）

## 5. 设备场景检查（拆桨）

软件侧按 API 勾「有 `takeoff`、有 `reconnect`」。设备侧按 **接线 → 身份 → 总线 → 掉线 → 飞控反应** 查。代码对了但波特率 / sysid / 总线争用错了，真机照样连不上或误控。

0.2 预览：**本包通过条件仍是第 2 节链路矩阵。** 下面飞行相关项用来发现接口坑，失败记在限制表，不把 SDK 当成已交付飞行。

```
物理口和波特率
    → 本端身份 sysid/compid
        → 总线上还有谁
            → 锁定哪颗飞控心跳
                → 遥测是否把口堵死
                → 机型能力是否允许该动作
                    → 拔线 / 掉电 / 进程挂
                        → 飞控 RC / 机载丢失参数
```

### 5.1 按真实接线分场景，不要混着测

每条场景只改 URI，其它脚本不变。URI 与默认身份见 [供应商集成说明.md](供应商集成说明.md) 和 [`ConnectionConfig`](../src/drone_fc/types.py)。

| 场景 | 典型 URI | 设备上要先确认 | 代码侧要盯 |
|------|----------|----------------|------------|
| 笔记本 USB | `serial:/dev/ttyACM0:57600` | 设备节点、`dialout`、57600、QGC 不要独占口 | 打不开 → `TransportOpenError`（含缺 `pyserial`），不是「没心跳」 |
| Jetson TELEM2 | `serial:/dev/ttyTHS1:921600` | 飞控 TELEM2 波特率、TX/RX 交叉、3.3V、`nvgetty` 是否占口 | 默认身份 1/191 是否和飞控 sysid=1 共存 |
| 树莓派 UART | `serial:/dev/serial0:921600` | `enable_uart`、串口控制台关掉 | 同上；路径因镜像而异 |
| 机载 mavlink-router | `udp:127.0.0.1:14540` | router 是转发还是独占；本机监听还是对外 | `udp:` 解析成 **udpin 监听**（[`connection.py`](../src/drone_fc/mavlink/connection.py)），方向错会静默无包 |
| 地面笔记本 + 数传 | `udp:...` 或 USB | 和机载计算机抢同一条总线 | 不得把 GCS 心跳当成飞控；看 `other_heartbeats` |
| ArduPilot SITL | `tcp:127.0.0.1:5760` | 仅仿真 | 不能用这条结论外推 TELEM2 真机 |

每条场景跑（不解锁）：

```bash
python examples/companion_check_link.py --uri serial:/dev/ttyACM0:57600
```

过关标准只有：英文 `Link OK`、`firmware` / `airframe` 与实机一致、`armed=False`。

失败时不要先改业务代码，先看异常字段：

| 异常 | 先查什么 |
|------|----------|
| `TransportOpenError` | 路径、权限、被占用、缺 `pyserial` |
| `HeartbeatTimeoutError` 且 `packets_seen=0` | 线、波特率、电源 |
| `HeartbeatTimeoutError` 且 `other_heartbeats>=1` | 总线上有 GCS/相机，没有 PX4/ArduPilot |
| `HeartbeatTimeoutError` 有包但无飞控心跳 | 回环或本端 sys/comp 配错 |

### 5.2 身份与总线

真机不是一对一 socket，是 **一条 MAVLink 总线**。对照 [`controller.py`](../src/drone_fc/mavlink/controller.py)：

1. **本端是谁。** 默认 `source_system=1, source_component=191`（机载）。笔记本 GCS 必须改成 255/190。机载和飞控常共用 sysid=1，只比 sysid 会把飞控心跳丢掉。`_is_own_source` 必须 **sys+comp 同时匹配**。
2. **锁定哪颗心跳。** 只锁 `autopilot` 为 PX4(12) / ArduPilot(3) 的 HEARTBEAT，忽略相机 / OSD / GCS。`HEARTBEAT.type=26` 是云台，不能当飞控。
3. **命令打到谁。** `connect` 成功后 `target_system` / `target_component` 必须来自那条飞控心跳，不能写死 1/1。
4. **QGC 同时开着是常态。** 仍须识别飞控、不把 GCS 当目标；57600 上两家抢流可能丢包。
5. **本端约 1 Hz 心跳。** `_maybe_send_heartbeat` 只在 `telemetry` / `wait_telemetry` / `spin` / 等心跳时泵送。应用 `connect` 后去跑视觉线程、不再调这几个方法，飞控会认为机载丢失——这是设备场景问题，库不会后台重连。

### 5.3 串口物理层

USB 57600 和 TELEM2 921600 不是同一条链路。

- 本库不发 `MAV_DATA_STREAM_ALL`，只订约 4 Hz 的 SYS_STATUS / GPS / ATTITUDE / GLOBAL_POSITION_INT / BATTERY_STATUS / GIMBAL_MANAGER_INFORMATION（`_request_telemetry_rates`）。
- 订阅失败被忽略时，真机可能 **永远没有位置**，`wait_telemetry` 变成 `TelemetryTimeoutError`，看起来像起飞失败。
- 波特率只在 URI 里；代码不会读飞控 `SER_TEL2_BAUD`。URI 与参数不一致 → `packets_seen=0`。
- 没有 RTS/CTS、没有 8N1 配置入口。供应商若开了流控，这是缺口。
- USB 重插后 `ttyACM0` 可能变成 `ttyACM1`。库不封装设备路径发现。调用 `reconnect(uri="serial:/dev/ttyACM1:57600")` 换节点；仍用旧 URI 会 `TransportOpenError`。

拔插检查（进程必须停在 `spin` / `wait_telemetry` / `telemetry` 上。`companion_check_link.py` 拍完快照就退出，不能用来干等拔线）：

1. 拔 USB / 断 TELEM2 → 约 3 秒 `LinkLostError`。
2. 插回同一节点 → `reconnect()`；若变成新节点 → `reconnect(uri=...)`。
3. 确认 pymavlink `autoreconnect=False`，库不会偷偷重开串口。

### 5.4 飞控侧安全

companion 崩了之后飞机做什么，查 **飞控参数**，不是查 Python。本库不替代遥控器。

- PX4：机载丢失 / RC 丢失一类参数（如 `COM_OBL_RC_LOSS`、`NAV_RCL_ACT`，以你们固件文档为准）。
- ArduPilot：如 `FS_GCS_ENABLE`、`FS_THR_ENABLE`。

库侧只确认：

- 从不强制解锁（ARM 的 param2 不是 21196）。
- 室外保持 `skip_gps_check=False`。`examples/sitl_takeoff_land.py` **默认不跳过 GPS**；SITL/mock 须显式传 `--skip-gps-check`。**禁止**带该开关在真机起飞。
- `takeoff` / `land` 的 ACK 成功 ≠ 飞机已到位；高度/接地必须用 `wait_telemetry`，超时必须失败。
- 单线程：相机 / 推理线程不得共用同一个 `MavlinkFlightController`。

### 5.5 换机之后

换机只改 URI，先看 `telemetry().vehicle_class` 和 `capabilities`，再决定能不能发命令。

| 实机 | 代码应出现 | 危险误用 |
|------|------------|----------|
| 四旋翼 PX4 / ArduCopter | `COPTER`，有 `land` / `takeoff` | 把 ArduCopter 模式号套到 Plane |
| 固定翼 | `PLANE`，**无** `land`，应 `rtl` | 仍调 `land()` 应立刻 `UnsupportedCapabilityError` |
| QuadPlane | `VTOL`，起降落走 Q* 模式表 | 当成纯固定翼或纯多旋翼 |
| 车 / 船 | `UNKNOWN`，飞行命令全拒绝 | 被当成飞机 |
| 云台在总线上 | 之后 `GIMBAL` 才为真 | 把云台心跳当成飞控；把 `set_gimbal` 当成图传（本库不做视频） |

Offboard：库在尚未 GUIDED/OFFBOARD 时会 **先发一帧设定点再切模式，切后再发一帧**（见单测）。调用方仍须 ≥约 2 Hz 循环发送。0.2 不验收真机 Offboard 飞行。

### 5.6 现场顺序

1. 飞控上电，QGC 能看见心跳 → 关掉 QGC 或确认不独占串口。
2. `companion_check_link.py` 使用该场景 URI → 身份、机型、GPS、电压。
3. 拔线 / 杀进程：`LinkLostError`，以及飞控 failsafe 是否按参数动作（悬停 / 降落 / RTL）。
4. `reconnect()`；USB 节点变了则 `reconnect(uri=...)`。
5. 另一台机（换固件或换机型）只跑 `vendor_same_control.py --dry-run`：能力表对不对。固定翼不得出现可 `land`。
6. **不要**用无 `--dry-run` 的 `vendor_same_control.py` 在室内无 GPS 真机上起飞。

函数覆盖率解决不了：错波特率、sysid 冲突、QGC 抢总线、USB 重枚举、57600 堵口、companion 停止泵心跳导致飞控判丢失。这些只能按上面的场景在真机（或至少 TELEM2 环回）上暴露。
