# 供应商集成说明

本文给 **飞机制造商 / 飞控供应商**：如何把本 SDK 接到你们的 PX4 或 ArduPilot 飞机上。应用方只调同一套 API，不按固件或机型写分支。

**本包是 0.2 工程预览。** 验收范围以 [已知限制.md](已知限制.md) 为准：已验证的是链路（心跳、超时排障、掉线、`reconnect`），不是多机型飞行。真机按接线检查见 [已知限制.md 第 5 节](已知限制.md)。

内部产品说明见 [需求文档.md](需求文档.md)。运行命令总表见根目录 [README.md](../README.md)。

---

## 1. 你们拿到什么

| 项 | 说明 |
|----|------|
| Python 包 `drone-fc` 0.2 | `FlightController` 统一接口（工程预览） |
| 本包验收 | PX4 多旋翼 mock：连通、心跳超时诊断、`LinkLostError`、调用方 `reconnect()` |
| 接口已写、未验收 | 固定翼/垂起飞行、航线握手、Offboard 流、云台指向（不是视频） |
| 不做 | 武器、无人车/船、图传视频、替你们改飞控参数或替代遥控器、MAVLink2 signing |

安装（在交付的源码或 wheel 上）：

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[plot]"    # 源码目录；只要飞控不要图则 pip install -e .
# 需要 pyserial（已列入核心依赖）才能打开 USB/UART
# 若只给 wheel：pip install drone_fc-0.2.0-py3-none-any.whl
```

供应商应用 **只** `import drone_fc`，不要 `import pymavlink`。

## 2. 飞机侧必须满足

拆桨后再接 SDK。本库 **从不强制解锁**。

1. 飞控固件为 **PX4** 或 **ArduPilot**（多旋翼 / 固定翼 / QuadPlane 垂起）。
2. 对机载计算机或联调电脑开放 MAVLink：**TELEM2 串口** 或 USB，或 `mavlink-router` 转到 UDP。
3. 波特率与 URI 一致（常见 USB `57600`，TELEM2 `921600`）。
4. 飞控心跳 `HEARTBEAT.autopilot` 为 PX4(12) 或 ArduPilot(3)；`HEARTBEAT.type` 为对应 `MAV_TYPE`（四旋翼=2，固定翼=1，垂起=19–25）。
5. 室外起飞需要 3D GPS（`fix_type >= 3`）。仿真才允许 `skip_gps_check=True`。
6. 进程挂掉后的行为由飞控 **RC 丢失 / 机载丢失** 参数决定，本库不替代遥控器。

URI 示例：

| 场景 | URI |
|------|-----|
| 飞控 USB | `serial:/dev/ttyACM0:57600` |
| Jetson TELEM2 | `serial:/dev/ttyTHS1:921600` |
| 树莓派 UART | `serial:/dev/serial0:921600` |
| 本机 mavlink-router / PX4 SITL | `udp:127.0.0.1:14540` |
| ArduPilot SITL | `tcp:127.0.0.1:5760` |

IPv6 字面量暂不支持，请用 IPv4 地址或主机名。

默认本端身份：sysid=1、comp=191（机载计算机）。地面站笔记本用 `source_system=255, source_component=190`。

Linux 串口需要 `dialout` 组。

## 3. 同一套控制（供应商验收脚本）

换机只改 URI。先识别，再按能力调用，不要假设固定翼也能 `land()`。

```python
from drone_fc import Capability, ConnectionConfig, MavlinkFlightController

fc = MavlinkFlightController(ConnectionConfig("serial:/dev/ttyACM0:57600"))
fc.connect()
snap = fc.telemetry()
print(snap.autopilot, snap.vehicle_class)
print(sorted(c.value for c in snap.capabilities.supported))

if snap.capabilities.supports(Capability.TAKEOFF):
    fc.takeoff(10.0)
    fc.wait_telemetry(
        lambda s: s.position is not None and s.position.altitude_m is not None and s.position.altitude_m >= 8.0,
        30.0,
    )

if snap.capabilities.supports(Capability.LAND):
    fc.land()
else:
    fc.rtl()   # 纯固定翼无独立降落模式

fc.disconnect()
```

命令在飞控 **ACK 后返回**，不等于已经飞到。到位用 `wait_telemetry`（阻塞收包，不要 `sleep`）。条件未满足时抛 `TelemetryTimeoutError`，不要继续发 `land` / `goto`。

`--dry-run` 只识别固件、机型、能力，不解锁。本预览建议供应商先跑 dry-run 与拆桨链路脚本。

无真机时可用仓库内协议 mock（不是物理仿真）：

```bash
python examples/mock_px4_mavlink.py          # 终端 1
python examples/check_connection.py          # 终端 2
```

真机拆桨只测链路（不解锁）：

```bash
python examples/companion_check_link.py --uri serial:/dev/ttyACM0:57600
```

## 4. 能力对照（供应商按机型勾选）

`connect()` 之后以 `telemetry().capabilities` 为准，下表为默认画像。

| 动作 | 多旋翼 | 固定翼 | 垂起 |
|------|--------|--------|------|
| `arm` / `disarm` / `set_mode` / `goto` / `rtl` | 有 | 有 | 有 |
| `takeoff` | 有，相对高 (0, 100] m | 有，(0, 500] m，不是垂直爬升 | 有，(0, 100] m |
| `land` | 有 | **无**（请用 `rtl` 或航线） | 有 |
| 航线 `upload_mission` / `start_mission` | 有 | 有 | 有 |
| `set_position` / `set_velocity` | 有 | 有 | 有 |
| 云台 | 总线上出现云台后才有 | 同左 | 同左 |

做不到的动作立即 `UnsupportedCapabilityError`，不会静默发错模式。航线 / Offboard / 云台在能力表里可能为真，**0.2 不作为协议验收项**。

Offboard / Guided 设定点：**调用方**循环 `set_position`/`set_velocity` 与 `spin`/`telemetry`，库不另开线程。PX4 Offboard 需约 2 Hz 以上。云台是指向命令，不是摄像头视频流。

单位：经纬度 WGS84 度；高度为相对 Home 米；姿态为度。

## 5. 异常（联调时请带回这几类）

| 异常 | 常见原因 |
|------|----------|
| `TransportOpenError` | 打不开串口/套接字（路径、`dialout` 权限、地址） |
| `HeartbeatTimeoutError` | 超时仍无飞控心跳；看 `packets_seen` / `other_heartbeats` / `last_msg_type` 判断是完全无包、只有 GCS/相机心跳，还是回环 |
| `LinkLostError` | 曾经连上，飞控心跳超过约 3 秒未到。调用 `reconnect()`，库不会后台重连 |
| `ArmDeniedError` | 预解锁未过；异常可能带最近 `STATUSTEXT`。请用 QGC 看完整列表 |
| `GpsNotFixedError` | 无 3D 定位 |
| `UnsupportedCapabilityError` | 该机型或当前 SDK 不做这个动作 |
| `UnsupportedModeError` | 该固件/机型没有这个语义模式 |
| `CommandFailedError` | 飞控拒绝或 ACK 超时 |
| `TelemetryTimeoutError` | `wait_telemetry` 在超时前条件仍为假；`telemetry` 字段是最后一帧快照 |

## 6. 链路不是登录

MAVLink **默认无认证**。`connect()` 只打开套接字或串口并等待飞控 `HEARTBEAT`，不是账号登录。

- **UDP**：同一网段内任意进程都可以向该端口发命令。
- **串口**：能打开设备节点即等于物理接触。
- 地面站、机载计算机、OSD **同时**挂在一条链路上是 MAVLink 常态，不是 SDK 独有的缺口。

本版本 **不实现 MAVLink2 signing**。需要防伪造时，请在网络层隔离（仅本机 `mavlink-router`、串口不对外转发）。后续可选把 `signing_key` 交给 Transport；不要把 `connect()` 成功理解成「对方不能连」。

掉线后由调用方执行 `reconnect()`（关闭 → 再打开 → 再等心跳）。USB 重插后若节点变了，传新 URI：`reconnect(uri="serial:/dev/ttyACM1:57600")`。一连接一线程。Transport **关闭** pymavlink `autoreconnect`，库不会在后台重开串口。

`connect` 后会请求常用遥测约 4 Hz。若发送失败，见 `fc.telemetry_rate_errors`（英文 logging warning），位置长期为 `None` 时先查这里。

## 7. 交付与许可

- 源码与 wheel 仅按合同提供，禁止再分发源码（见仓库 `LICENSE`）。
- 运行时依赖 `pymavlink` 为 LGPLv3，须保持可替换（`pip` 安装），不要打进不可替换的静态包。
- 单测（无真机）：`python -m unittest discover -s tests -v`

链路是否正确，按三层测（不要改内部时间戳冒充掉线）：

1. **逻辑**：`python -m unittest tests.test_link -v`（假 Transport，无套接字）。
2. **UDP 仿真**：`python -m unittest tests.test_link_udp -v`（子进程拉起 `examples/mock_px4_mavlink.py`）。覆盖：连通成功；空端口 `HeartbeatTimeoutError`；只有 GCS 心跳时 `other_heartbeats >= 1`；坏串口 `TransportOpenError`；杀掉 mock 后 `LinkLostError`，再 `reconnect()`。无 pymavlink 则跳过。
3. **真机（拆桨，不进 CI）**：按 [已知限制.md 第 5 节](已知限制.md) 分场景（USB / TELEM2 / UART / UDP），不要混着测。`python examples/companion_check_link.py --uri serial:/dev/ttyACM0:57600` 证明心跳。该脚本拍完快照就退出，不会一直等到拔线。若进程停在 `wait_telemetry` / `spin` / `telemetry`，拔线应 `LinkLostError`；插回后 `reconnect()`，节点变了则 `reconnect(uri=...)`。

手动等价：

```bash
python examples/mock_px4_mavlink.py --port 14550
python examples/check_connection.py --uri udp:127.0.0.1:14550 --timeout 5
# 停掉 mock 后再跑，预期英文：link failed 且 packets_seen= / fc_heartbeats=0
python examples/check_connection.py --uri udp:127.0.0.1:14550 --timeout 2
```

供应商本包建议最少三项（见 [已知限制.md](已知限制.md)）：

1. 拆桨链路脚本打印 `Link OK`，`vehicle_class` 与实机一致。
2. `python -m unittest discover -s tests -v` 通过。
3. dry-run 识别另一固件或另一机型的心跳与能力（固定翼应看到无 `land`）。**不要求本包完成该机型起飞验收。**

现场顺序（永远拆桨）：QGC 能看见心跳 → 关掉或确认不独占串口 → `companion_check_link.py` → 拔线看 `LinkLostError` 与飞控 failsafe → 节点未变再 `reconnect()` → 另一机型只跑 `--dry-run`。不要用无 `--dry-run` 的 `vendor_same_control.py` 在室内无 GPS 真机上起飞。
