## 1. 产品一句话

这是面向测绘、巡检、科研仿真的 **商用闭源 Python 飞控 SDK**。

应用只依赖 `FlightController`。同一套脚本可以接 **PX4 或 ArduPilot** 的 **多旋翼、固定翼、垂起**。换机、换固件时，业务代码不写 `if px4` / `if plane`。

**同一控制**指：同一方法名、同一成功/失败语义（ACK 后返回；到位用 `wait_telemetry`）。不是每种机的物理过程都一样——固定翼起飞不是垂直爬升。某机做不到的动作在 `connect` 之后的能力画像里为假，调用立即抛 `UnsupportedCapabilityError`，不静默乱发命令。

范围限定民用飞行。不包含武器投放、目标打击或轰炸调度。

## 2. 要统一的两根轴

客户看到的是语义动作：`arm`、`takeoff`、`goto`、`land`、`rtl`、`set_mode`，以及后续的航线、设定点、云台。库把动作译成 **该机型 × 该固件** 的 MAVLink。

| 轴 | 取值 | 谁来填 |
|----|------|--------|
| 固件 | `PX4`、`ARDUPILOT` | `HEARTBEAT.autopilot`（12 / 3） |
| 机型 | `COPTER`、`PLANE`、`VTOL` | `HEARTBEAT.type`（`MAV_TYPE_*` 归类） |

无人车、船、潜艇不在本产品内：识别为 `UNKNOWN`，飞行类动作一律拒绝。

```
客户脚本
    └── FlightController（稳定商用 API）
            └── 能力画像 CapabilityProfile
                    ├── COPTER × PX4 / ArduCopter
                    ├── PLANE  × PX4 / ArduPlane
                    └── VTOL   × PX4 / ArduPilot QuadPlane
```

## 3. 能力画像

`connect()` 成功后，遥测带上 `vehicle_class` 与只读 `capabilities`。无能力的方法禁止发往飞控。

| 动作 | 多旋翼 COPTER | 固定翼 PLANE | 垂起 VTOL |
|------|----------------|--------------|-----------|
| `arm` / `disarm` | 支持 | 支持 | 支持 |
| `set_mode` | 支持 | 支持 | 支持 |
| `takeoff` | 支持（垂直爬升，(0, 100] m） | 支持（跑道/手抛/自动起飞，(0, 500] m） | 支持（多旋翼起降，(0, 100] m） |
| `goto` | 支持 | 支持 | 支持 |
| `hold`（`HOLD` 模式） | 支持 | 支持（盘旋） | 支持 |
| `land` | 支持 | **无**（请用 `rtl` 或航线） | 支持（多旋翼降落） |
| `rtl` | 支持 | 支持 | 支持 |
| 航线 Mission | 支持 | 支持 | 支持 |
| Offboard / Guided 设定点 | 支持（调用方循环 `spin`+setpoint） | 支持（同上） | 支持 |
| 云台 Gimbal | 见到云台心跳或 `GIMBAL_MANAGER_INFORMATION` 后为真 | 同左 | 同左 |

约束：

- Copter 起飞高度相对 Home，单位米，范围 (0, 100]。Plane 起飞 (0, 500] m，无独立 `land`（用 `rtl`）。VTOL 起飞/降落按多旋翼高度尺 (0, 100] m。见 FC2-08。
- `takeoff` / `goto` / `land` / `rtl` 在飞控 ACK 后返回，不等待到位。
- 公开 `FlightMode` 集合保持稳定：`MANUAL`、`HOLD`、`MISSION`、`RTL`、`LAND`、`TAKEOFF`、`GUIDED`。`UNKNOWN` 禁止用于 `set_mode`。
- 上表是产品目标画像。**0.2 预览：航线 / Offboard / 云台协议未验收**（能力位可能为真，但不代表已联调）。

## 4. 用户与场景

| 角色 | 场景 |
|------|------|
| 应用开发 | 一套巡检脚本，换机只换 URI，不写固件分支、不写机型分支 |
| 飞控联调 | 无真机时用协议模拟验证心跳、识别（固件+机型+能力）、解锁、起飞、降落 |
| 机载联调 | 拆桨后用串口脚本确认心跳与 GPS，不解锁 |
| 仿真使用者 | 改 URI 从 mock 切到 PX4 SITL 或 ArduPilot SITL；协议 mock 不是物理仿真 |

## 5. V1 基线（历史：两套固件 × 仅多旋翼）

编号 **FC-**。这是最早验收范围。第 6 节是后续接口；**0.2 不要把航线/Offboard/云台写成已验收。** 见 [已知限制.md](已知限制.md)。

### 5.1 连接与识别

| ID | 需求 | 约束 |
|----|------|------|
| FC-01 | 支持 URI：`udp:host:port`、`tcp:host:port`、`serial:device:baud`，以及显式 `udpin` / `udpout` | 端口 [1, 65535]；波特率 [1200, 1000000] |
| FC-02 | `udp:host:port` 默认转为监听（`udpin`），以适配 PX4 SITL 向 14540 发数 | — |
| FC-03 | `connect()` 打开传输并在超时内收到飞控 HEARTBEAT，识别 PX4 / ArduPilot | 超时必须为有限数 > 0；打开失败为 `TransportOpenError`；超时为带收包计数的 `HeartbeatTimeoutError`；示例不再 sleep |
| FC-03a | 已连接后飞控心跳超过约 3 秒未到则 `LinkLostError`；`reconnect()` 关闭后再连 | 不后台重连；一连接一线程 |
| FC-04 | 忽略本端 (sys,comp) 心跳；只把 PX4/ArduPilot 飞控心跳锁定为命令目标 | 机上总线可能还有相机/OSD，不得用第一个心跳 |
| FC-04a | 默认机载身份：sysid=1、comp=191、`MAV_TYPE_ONBOARD_CONTROLLER`，约 1 Hz 保活 | 地面站可改为 255/190 |
| FC-04b | 遥测订阅读位置/GPS/姿态/电源约 4 Hz，不发送 `MAV_DATA_STREAM_ALL` | 避免低速 UART 堵口 |

### 5.2 控制（多旋翼）

| ID | 需求 | 约束 |
|----|------|------|
| FC-05 | 语义模式：`MANUAL`、`HOLD`、`MISSION`、`RTL`、`LAND`、`TAKEOFF`、`GUIDED` | `UNKNOWN` 禁止用于 `set_mode` |
| FC-06 | 未收到心跳禁止解锁 | — |
| FC-07 | 起飞前默认要求 GPS `fix_type >= 3`；仅仿真可 `skip_gps_check=True` | 多旋翼起飞高度 (0, 100] 米 |
| FC-08 | `takeoff` / `goto` / `land` / `rtl` 在飞控 ACK 后返回，不等待到位 | 调用方用 `wait_telemetry()`（阻塞 recv，不用 sleep）。条件未满足时抛 `TelemetryTimeoutError`，不得当成功继续 |
| FC-09 | `goto`：纬度 [-90, 90]、经度 [-180, 180]、相对高 (0, 500] 米 | PX4 优先 `DO_REPOSITION`，不支持则 GUIDED + 位置设定点 |
| FC-10 | 命令失败抛异常，不静默死循环重试 | — |

### 5.3 遥测

| ID | 需求 | 单位 |
|----|------|------|
| FC-11 | 快照含固件类型、模式、解锁、位置、姿态、电池、GPS | 经纬度：度（WGS84）；高度：相对 Home 米；姿态：度 |
| FC-12 | 尚未收到的字段为 `None`，不编造数据 | — |

### 5.4 仿真与可视化（辅助，非物理引擎）

| ID | 需求 |
|----|------|
| FC-13 | 提供协议级 PX4 模拟端：心跳、GPS、位置、命令 ACK，无需 Gazebo |
| FC-14 | 提供连通检查脚本与起飞降落示例 |
| FC-15 | 提供 matplotlib 2D 图：东/北米轨迹 + 高度–时间 |

### 5.5 V1 验收记录

| 项 | 结果 |
|----|------|
| 模式映射 + URI 单测 | `python -m unittest discover -s tests` 通过 |
| 协议模拟连通 | 识别 PX4，GPS 3D，可读位置与电压 |
| 起飞 / 平移 / 降落 + 2D 图 | `examples/live_telemetry_plot.py` 可跑通 |
| 机载身份与遥测订阅 | 默认 191 onboard 心跳；不使用 DATA_STREAM_ALL |
| 到位等待示例 | `examples/sitl_takeoff_land.py` 按高度遥测判断爬升/接地 |

## 6. 机型统一（接口已写；协议未作为 0.2 验收）

编号 **FC2-**。应用仍只调 `FlightController`。Copter 旧脚本不得破坏。  
**0.2 预览只验收连接诊断 + 模式/能力表单测。** 下表「代码状态」不是供应商飞行验收。

| ID | 需求 | 0.2 状态 |
|----|------|-----------|
| FC2-01 | 从 `HEARTBEAT.type` 识别 `VehicleClass`，写入遥测 | 已实现 + 单测。无 Plane/VTOL mock 飞行 |
| FC2-02 | 提供只读 `CapabilityProfile` | 已实现 + 单测；无云台则 GIMBAL 为假 |
| FC2-03 | 模式表覆盖 PX4/ArduPilot × Copter/Plane/VTOL | 已实现 + `tests/test_modes.py` |
| FC2-04 | 无能力的动作立即 `UnsupportedCapabilityError` | 已实现；固定翼 `land()` 有控制器级单测 |
| FC2-05 | Mission：上传 / 开始 / 暂停 / 清除 | **接口已暴露**；仅航点校验单测；mock 无 `MISSION_*`；**未验收** |
| FC2-06 | Guided/Offboard：位置与速度设定点 | **接口已暴露**；无协议测试；**未验收** |
| FC2-07 | 云台朝向 / 回中（Gimbal Protocol v2） | **接口已暴露**；不是视频流；**未验收** |
| FC2-08 | Plane/VTOL 的 takeoff/land 参数与流程单独规定 | 高度尺已实现（Copter/VTOL 100 m，Plane 500 m）。**真机/SITL 未验收** |

V1 遥测在 FC2 中增加：`vehicle_class`、`capabilities`（未识别前为 `None`）。

## 7. 非功能需求

| ID | 需求 |
|----|------|
| NF-01 | 应用只依赖 `FlightController` 抽象，不直接 `import pymavlink` |
| NF-02 | 实现类不保证线程安全，同一连接单线程使用 |
| NF-03 | 公开方法注释写清输入、输出、失败、是否阻塞及合法范围 |
| NF-04 | 模式映射、URI 解析、机型归类与能力拒绝有不依赖真机的单元测试 |
| NF-05 | Python 3.10+；核心依赖写在 `pyproject.toml` 与 `requirements.txt`（`pymavlink`、`pyserial`）；绘图为 `[plot]` 可选 |
| NF-06 | MAVLink 收发隔离在 Transport 之后。开发期可用 pymavlink；商用闭源发行不得把 LGPLv3 打进产品 wheel（目标为 MIT 生成方言或 BSD/MIT 客户端） |
| NF-07 | 不引入 ROS / rclpy 作为核心运行时 |

## 8. 明确不做

- 武器投放、目标打击、摧毁列表、自动出击等作战链路
- 无人车、无人船、潜艇（可识别为 `UNKNOWN` 并拒绝飞行命令，不提供地面/水面 API）
- 本阶段不做：机载计算机设备路径封装、Gazebo/AirSim/JSBSim 统一仿真入口、推理后端、4G/数传/SDR 桥、多机编队

固定翼与垂起 **属于产品范围**（见第 6 节），不再列为「不做」。

## 10. 相关工作与许可

学架构、自研实现，不把 GPL/ROS 栈并进闭源产品：

- UAV Abstraction Layer（UAL）：统一 takeoff/goto/land，差异在 Backend
- Aerostack2：平台无关 + 能力/行为，而不是「所有机型同一套物理起飞」
- MAVSDK：Action / Mission / Offboard / Gimbal 的客户可见划分（BSD-3，可对照不可当本 SDK 内核）

模式号与 `MAV_TYPE` 以 PX4、ArduPilot 官方头文件和 MAVLink XML 为准。
